# Docket on a phone

The two app shells, as a tappable prototype: the client PWA at `/app` and the
lawyer console at `/firm`, each in an iPhone and an Android frame. It is a
design artboard, not shipping code — the code it describes is in `app/app/` and
`app/firm/`.

    Docket PWA.dc.html   the artboard: 19 screens, two shells, one state machine
    ios-frame.jsx        device bezel, status bar, home indicator
    android-frame.jsx    device bezel, status bar, gesture pill
    canvas.json          frame size and launch view for the design canvas

`.dc.html` is a Claude Design artboard. The `./support.js` line in the head and
the `<x-dc>` / `<helmet>` wrapper are the canvas runtime and must stay verbatim.
`support.js` itself is generated by the canvas and is not kept here.

The device frames are the mockup's furniture, not the app's. Nothing in
`ios-frame.jsx` or `android-frame.jsx` has an equivalent in the codebase: the
status bar belongs to the phone, and the artboard's fixed `topPad` / `botPad`
are `env(safe-area-inset-*)` in the real thing.

## The rule that matters

**The client app wears the firm's colours. The console wears none.**

A client opening `/app` is dealing with their lawyers, not with Docket, so the
client shell takes `--pri`, `--acc` and its heading face from `firms.brand` —
Attorneys Klinique's navy and gold, Bello & Co's oxblood and sage. A lawyer
opening `/firm` is holding the same working tool whichever firm they opened it
for, so the console is fixed neutral: `#141414` ink, `#57534E` grey, `#F5F4F1`
ground, Archivo. Colour in the console means one thing only — something is
late, unpaid, or waiting on you.

Both shells are built from one set of components (`src/components/app/`) over
one set of semantic tokens (`--dk-app-*` in `app/globals.css`), so a card, a
row or a pill is the same component in both places and only the palette moves.
A firm cannot repaint the console by choosing a brand colour, because no
console token reads a firm token.

| token | client | console |
| --- | --- | --- |
| `--dk-app-pri` | firm primary | `#141414` |
| `--dk-app-acc` | firm accent | `#57534E` |
| `--dk-app-acc-ink` | accent darkened to 6:1 on white | `#57534E` |
| `--dk-app-surface` | firm surface | `#F5F4F1` |
| `--dk-app-head` | firm heading face | Archivo |
| `--dk-app-line` | `#E5E7EB` | `#DDD9D2` |
| `--dk-app-rule` | `#F3F4F6` | `#F0EEEA` |

`--dk-app-acc-ink` exists because an accent chosen to be drawn as a colour is
usually too light to be read as one: Klinique's `#B08D57` is 2.6:1 on white,
well under the 4.5:1 floor. `accentInk()` in `src/lib/brand.ts` walks it down
in luminance until it clears 6:1, which is where the artboard's own hand-picked
inks sit (`#7A5F33` is 5.98:1, `#5A6152` is 6.43:1). The accent itself is
untouched wherever it is a fill or a border.

Status colour is never the only signal: every pill carries an icon and a word.

## What the prototype shows that the code does not

The artboard is a prototype, so some of it is drawn rather than built. These
three were new to the design and are **not** implemented as drawn:

**The offline copy.** The artboard shows a home banner reading "Saved 11 Sept,
09:14 — court dates and the matter timeline are readable". The service worker
caches no private data on purpose: `public/sw.js` is network-first for
navigations with an offline page as the fallback, and every screen behind it is
RLS-scoped data belonging to somebody's legal matter. The banner and the
Profile row are built, and they react to the real connection, but they claim
only what the service worker actually holds — the app shell — and no saved-at
time is shown, because nothing is saved. Caching matters and court dates for
real means putting privileged material on the device at rest, which is a
decision about client confidentiality, not about layout.

**The firm switcher.** The artboard repaints the whole app in the chosen firm's
colours from a bottom sheet. `/app` takes its tenant from the request host —
the middleware resolves a custom domain or a `{slug}.docket.app` subdomain and
stamps `x-firm-id` (blueprint §4). The Profile card and the sheet are built and
they list the firms the signed-in person genuinely has matters or appointments
with, but choosing one navigates to that firm's own address rather than
repainting in place. Repainting in place would mean the tenant came from a
cookie instead of the host, and a firm's surface would then be reachable from
another firm's domain.

**The lawyer call screen.** The console's admit-and-call screen is drawn in the
artboard against the same Daily room the client uses. The room, the owner token
and the waiting-room admission already exist in
`src/components/video/consultation-room.tsx`; what the artboard adds is the
phone layout for it.

Everything else on the artboard is built.

## Working on it

The artboard renders in the Claude Design canvas, which supplies `support.js`,
React and the `<x-dc>` runtime. To put it back on the canvas, seed a fresh
payload with the `design` skill's `seed-canvas.mjs`, passing
`Docket PWA.dc.html`, both frames and `canvas.json`, then publish the seeded
file.

There is no `verify.mjs` here, unlike `design/home`. That page is one long
column of type where a wrong wrap clips an exhibit, so it is worth rendering
and measuring. This one is nineteen short screens inside a fixed device frame,
and the thing that would actually break — a tap target under 44px, a pill whose
colour is its only signal, a console screen that has picked up a firm's
colour — is checked in the components rather than in the picture.
